# DefaultSynth 작업 로그

## 2026-08-13 19:55:41 +09:00
- 작업: 빈 폴더(SYNTH.png 디자인 1장)에서 시작해 CLAP·VST3를 동시에 내보내는 폴리포닉 신스의 뼈대를 세우고 실제 번들 생성과 호스트 검증까지 완료함.
- 기술 선택: Rust + nih-plug으로 단일 코드베이스에서 CLAP·VST3를 export하고, GUI는 nih_plug_vizia(네이티브)를 사용함. VST3 바인딩이 GPLv3라는 점을 사용자에게 확인받고 진행함. CLAP은 MIT라 제약 없음. 사전에 GUI 툴킷과 DAW 호환성은 무관하다는 점(포맷이 호환성을 결정)을 정정함.
- 구조: 프레임워크 의존성이 전혀 없는 `crates/ds-dsp`(합성 코어)와 nih-plug 래퍼인 `crates/defaultsynth`로 분리해 DSP를 평범한 cargo test로 검증 가능하게 하고, 향후 VST3 경로를 JUCE로 교체하더라도 코어를 재사용할 수 있게 함. 번들링은 `xtask`.
- DSP 코어: PolyBLEP 안티에일리어싱 오실레이터(사인/삼각/톱/펄스, 유니즌 스택과 등파워 스테레오 스프레드), AHDSR 엔벨로프, ZDF 상태변수 필터(LP/HP/BP/Notch), White/Pink/Brown 노이즈, 오실레이터 3개+노이즈+필터 2개를 갖는 보이스, 보이스 할당·스틸링·Poly/Mono/Legato·포르타멘토 엔진을 구현하고 단위 테스트 48개를 붙임.
- 플러그인: 74개 파라미터를 UI 패널 구조에 맞춰 nested 그룹으로 정의하고, MIDI 노트온/오프/초크/CC123을 샘플 정확도로 처리하는 process 루프와 VIZIA 에디터 골격(모든 컨트롤이 실제 파라미터에 바인딩)을 구현함.
- 빌드 안정화: MiniDAW와 동일한 os error 32(인덱서/백신의 증분 오브젝트 잠금)가 재현되어 `.cargo/config.toml`의 build.target-dir로 빌드 캐시를 C:\tmp\defaultsynth-target으로 분리함.
- 검증 결과: `cargo xtask bundle`이 DefaultSynth.clap과 규격에 맞는 DefaultSynth.vst3 번들을 생성함(PE 시그니처 MZ 확인). clap-validator 44개 중 31 passed / 9 skipped / 4 failed.
- 검사기가 잡아낸 실제 결함 2건 수정: (1) Cutoff가 "1.1 kHz Hz"를 출력해 문자열 되읽기 실패 — v2s_f32_hz_then_khz가 이미 단위를 포함하는데 with_unit을 중복 지정한 것이 원인. (2) 파라미터 극단값에서 NaN 샘플 출력 — 마스터 게인 최솟값이 0인데 로그 스무딩을 걸어 로그 영역 보간이 발산. 최솟값을 -60 dB로 올려 해결. 아울러 Pan의 커스텀 value_to_string에 짝이 되는 string_to_value가 없어 파싱 불가였던 것도 함께 고침.
- 남은 4개 실패 판별: state-reproducibility 3종과 state-invalid-random 크래시는 nih-plug 공식 gain 예제를 같은 검사기로 돌렸을 때 동일한 4개가 동일 크래시 코드로 실패함(대조군 28 passed / 4 failed)을 확인해, 이 프로젝트 결함이 아니라 nih-plug과 clap-validator의 버전 불일치로 판별함. 해시 충돌 가설은 74개 ID의 nih-plug 해시를 직접 계산해 충돌 0으로 배제함.
- 추가 수정: 파라미터 스무더를 블록당 1회만 진행시켜 램프가 최대 64배 느려지던 문제를 next_step(block_len)으로 교정하고, 노트 이벤트마다 스무더를 추가로 진행시켜 램프 속도가 연주 밀도에 의존하던 문제를 비진행 스냅샷으로 분리함. 플러그인이 호스트 프로세스 안에서 동작하므로 패닉 시 DAW를 함께 죽이는 panic="abort"를 릴리스 프로필에서 제거함.
- 검증 총계: 워크스페이스 cargo test 52개(DSP 48, 파라미터 4) 통과, 릴리스 번들 생성 성공, clap-validator 31/44 통과(잔여 4건은 상기 프레임워크 이슈).
- 다음 단계: 커스텀 위젯(원형 노브, 파형 디스플레이, 엔벨로프·LFO 곡선 에디터)으로 디자인 재현, 그다음 웨이브테이블·LFO·모드 매트릭스·이펙트 랙·프리셋 브라우저 순서를 제안함.

- Filter B에 F1 입력을 추가함. 켜면 필터 A의 출력이 필터 B의 버스로 접히고 A는 믹스에 직접 도달하지 않아, 두 필터가 병렬에서 직렬로 바뀜. 필터 A에는 같은 옵션을 두지 않았는데 자기 출력을 자기 입력으로 받으면 루프가 되기 때문임. 병렬 대비 신호가 실제로 달라지는 것과 B 바이패스 시 레벨이 이중으로 커지지 않는 것을 각각 테스트로 고정함.
- GitHub 초기 커밋 후 https://github.com/Uranium10/DefaultSynth 로 푸시함(25개 파일). 커밋 전 정리: 빈 stray 파일 `trace` 제거, 그리고 `.cargo/config.toml`에 박혀 있던 머신 절대경로를 공개 저장소에 부적절하다고 판단해 alias만 남기고 빌드 캐시 경로는 `build.bat`으로 옮김(CARGO_TARGET_DIR 선설정 시 그 값 우선). 사용자가 취소해 LICENSE 전문 파일은 아직 넣지 않음.
- 디자인 재현 1단계: VIZIA에 로터리 컨트롤이 없어 원형 노브를 캔버스에 직접 그리는 커스텀 위젯으로 구현함. 270도 스윕, 값 아크, 포인터 라인, 세로 드래그, Shift 미세 조절(모디파이어 전환 시 재앵커링), 휠 스텝, Ctrl클릭·우클릭·더블클릭 리셋, 포인터가 창을 벗어나도 래치되지 않도록 MouseOut 해제를 포함함. 바이폴라 파라미터는 기본값이 가운데면 중앙에서 좌우로 채워지게 함.
- 파형 디스플레이 위젯을 추가해 OSC 패널의 다크 우물과 발광 트레이스를 재현함. 배경은 `cx.build_path()` + `draw_background()`로 그려 CSS 배경·라운드가 그대로 적용되게 하고, 트레이스는 넓은 반투명 스트로크 위에 얇은 스트로크를 겹쳐 글로우를 냄. 화면용이라 밴드리미팅 없는 이상적 파형을 그림.
- 에디터를 슬라이더 나열에서 디자인 구조로 재구성함. OSC 패널은 좌측 파형 우물 + 우측 노브 그리드(OCT/FINE/UNISON 인셋 리드아웃, DETUNE·BLEND·WARP·PHASE, RAND·PAN·VOLUME·FILTER), 필터/노이즈/엔벨로프/보이싱 패널도 노브 셀로 교체함. 노브 값 표시는 파라미터 자체 포매터를 써서 단위와 팬/게인 문자열이 자동으로 따라오게 함.
- API 차이 3건 교정: vizia::style::Color 경로 대신 impl Into<vg::Color>, 존재하지 않는 multi_click_count 대신 WindowEvent::MouseDoubleClick, border_radius_top_left 대신 build_path/draw_background. Handle<Self>의 elided lifetime 경고 2건도 Handle<'_, Self>로 정리해 경고 0.
- 검증: 워크스페이스 테스트 57개 통과(DSP 50, 파라미터 4, 파형 3), cargo check 경고 0, 릴리스 번들 생성 성공, clap-validator 31/44 유지(잔여 4건은 앞서 판별한 nih-plug/clap-validator 불일치).

- 엔벨로프 곡선 수식을 `EnvelopeSettings::stage_level`로 ds-dsp에 올리고 `Envelope::process`와 에디터 표시가 모두 이 함수를 쓰게 함. 그림과 소리가 갈라지지 않는다는 것을 "실행 중인 엔벨로프의 값과 stage_level이 각 구간 중간에서 일치한다"는 테스트로 고정함.
- 리팩터링 중 회귀를 하나 잡음: release를 sustain 기준으로 스케일하도록 바꿨더니 sustain이 0인 퍼커시브 패치에서 릴리즈가 즉시 끊겼음. 공통 감쇠 곡선 `exp_fall`을 빼내 process는 실제 릴리즈 시작 레벨에서, 표시는 sustain에서 떨어지도록 분리하고 회귀 테스트를 추가함.
- EnvelopeDisplay 위젯 구현: 다크 우물, 점선 구간 구분선, 실제 곡선 렌더링, 드래그 핸들 4개(attack, hold, decay+sustain, release). 시간 축은 디자인처럼 구간 길이에 비례 배분하되 각 구간에 최소 폭을 주어 길이 0인 구간도 잡을 수 있게 하고, sustain은 지속 시간이 없으므로 고정 폭을 배정함.
- 드래그 설계 판단: 시간 파라미터는 스큐가 심해 픽셀당 초가 일정하지 않으므로 정규화 공간에서 이동(우물 가로폭 횡단 = 전체 범위)하고, sustain은 선형 0..1이라 커서를 정확히 추종하게 분리함. Shift 미세 조절 시 재앵커링, 핸들 더블클릭 시 해당 파라미터만 기본값 복귀.
